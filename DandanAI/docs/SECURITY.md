# Security notes and known limitations
Implemented: Argon2id hashing, short-lived JWT with server-side revocation (token_version), per-process login throttle + constant-time-ish unknown-user path, role + case-level authorisation on every route with 404 on denial, org-scoped retrieval, upload validation (extension, magic bytes, size, server-generated storage keys), prompt-injection neutralisation, output prediction filter, security headers, generic 500 responses, production boot guards (weak JWT secret, test DB), audit log, CORS allow-list, no secrets in frontend.
Known limitations before production: JWT in `localStorage` (XSS exposure; move to httpOnly cookies + CSRF), login throttle is in-memory (use Redis), no email verification/password reset, no antivirus scanning of uploads, no encryption of extracted text at rest beyond Neon/storage defaults, no per-tenant row-level security in Postgres (isolation is application-enforced), BackgroundTasks are not durable (use a queue), dependency versions are unpinned lower bounds (pin + audit), no formal penetration test, legal text licensing not reviewed.
